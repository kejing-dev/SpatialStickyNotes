# Spatial Sticky Notes · 空间便利贴 (PICO Spatial SDK)

Offline, Shared Space sticky notes: the home window is the note list, and every note is its own planar window, pinned into the shared space as a bare yellow card. Tap a note to select it (the system caption bar appears with it; drag the bar to move the note), tap it again or tap ✎ to edit in place on the card; since v1.3 the card height follows the text (1–7 lines) and the note window grows and shrinks with its content, the ⤡ in the strip folds the note by hand into a small marker (the folded state is saved with the note and it is still folded after a restart), and a tap on the marker unfolds it; notes autosave locally, the text is restored after a restart, and window placement is left entirely to PICO OS. The whole UI is icon-only; the only text is the delete confirmation dialog (in English); note bodies can be in any language. Implemented from [PRD《空间便利贴》v0.1](https://bytedance.us.larkoffice.com/docx/Uo26dYsAqo5gQCxy1ECukgkqs0d) (PRD "Spatial Sticky Notes" v0.1, internal Lark document) and [Figma "PICO Spatial UI · PRD v0.2"](https://www.figma.com/design/H0KLCZUVvotKl3J2eF29mB/) (on the page「01 用户路径」(01 User Journey), sections 09 / 09b / 10 / 11 are the v1.2 final design and section 13「便签窗口 v1.3 · 手动收起 + 自适应高度」(Note window v1.3 · manual fold + adaptive height) is the v1.3 final design). Current version: `versionName 1.3`, `versionCode 4`.

## What changed in v1.3 vs v1.2

The user tested v1.2 on the headset: distance-based folding never triggered (the distance was only an estimate derived from the dp→metre conversion factor and is unreliable on a real device), so v1.3 replaces it entirely with manual folding and lets the card and window height follow the content.

- **Distance LOD removed**: `lod/ViewerDistance.kt` (`LodController`, `rememberViewerDistanceEstimate`) is deleted; there are no more 1.5 / 1.8 m thresholds, hysteresis or 200 ms sampling; the container still declares `WorldScale.Dynamic`, but no code reads the conversion factor any more.
- **⤡ manual fold, persisted**: the selected-state strip is now ✎ | 🗑 | ⤡ (`ic_collapse`, two inward-pointing chevrons, the opposite of the unfold badge on the marker). ⤡ folds the note into the 96 dp `StickyMarker`; a tap anywhere on the marker unfolds it; the folded state is written to `files/notes.json` as `"collapsed": true|false` (`Note.collapsed`, `NoteStore.setCollapsed`) and the note is still folded after a restart; `updatedAt` is not touched, so the list order is unchanged; drafts (new notes not yet confirmed with ✓) have no ⤡.
- **Adaptive card height**: `StickyCard` is still 328 dp wide; its height follows the text from 74 dp (1 line) to 254 dp (7 lines) (`Tokens.NoteCardMinHeight / NoteCardMaxHeight`, height = lines × 30 + 44); longer notes scroll inside the card; the inline editor is at least 4 lines tall (164 dp, `Tokens.NoteEditorMinHeight`) and grows with the text up to 254 dp.
- **Window follows the content height**: the note window is still 400 dp wide with `ContainerResizeType.ContentSize`; `NoteWindow` reports the measured content height to `Main.kt`, which pins the window to it with `windowConstraints(minHeight = maxHeight = contentHeight)` (the SDK resizes the container whenever the constraints change); the content is measured with an unbounded height, so the window can both shrink and grow. On the emulator: a 1-line note is 194 dp, 2 lines 220 dp, editing 284 dp; folded requests 144 dp and the system raises it to its ~180 dp minimum.
- **Tap fix**: `StickyCard` / `StickyMarker` are back to a plain `clickable` without indication — on PICO OS 6.1, `PicoTheme`'s default press indication / `spatialHoverEffect` kept taps from reaching the card (tap-again-to-edit and tap-marker-to-unfold silently did nothing).

## What changed in v1.2 vs v1.0

- **No placement state machine any more**: pending placement / pin here / move / put back into space and the `placement` field in the JSON are all removed; the note window's position and the surface it sits on are handled entirely by the PICO OS window system, and the app stores only text; a `placement` key in an old `notes.json` is ignored on read.
- **No separate editor window any more**: the 560 × 640 dp editor window (`NoteEditorWindow.kt`) is deleted; creating and editing both happen inline on the card in the note window; the container count goes from three to two.
- **Icon-only UI**: text buttons, `StatusPill`, the Snackbar and the `n / 200` counter text no longer exist, replaced by the `ActionStrip` icon strip, the `CounterRing` counter ring, and the title bar's "+" with a capacity ring and "!" retry icon (formerly the "retry save" text button).
- **The only UI text is English**: the "Delete" title of the delete confirmation dialog; the dialog buttons remain icon-only ✕ (cancel, secondary) / 🗑 (delete, danger), 120 × 52 dp with 28 dp icons; the app name is now "Spatial Sticky Notes". Note bodies can still be Chinese (the test data is Chinese); a Chinese UI is deliberately not provided.
- **The folded marker** changes from a 72 dp "≡" to the 96 dp folded mini-note `StickyMarker` (with an unfold badge); the note window's caption bar changes from auto-hide to always visible, as the only way to move the note.

## Interaction model

- **Selection == system window focus**: tap a note and PICO OS hands focus to that window; the system caption bar appears — drag it to move the note; the app itself provides no move or placement feature. When selected, the card gets a 2 dp accent outline and a pill-shaped `ActionStrip` appears centred directly below the card (12 dp gap): ✎ | 🗑 | ⤡ (no ⤡ on a draft) — the strip sits below the card rather than at a corner, so it never covers the note text; while the card is unfolded the strip's 60 dp slot is always reserved, so the window height does not jump on focus / unfocus. There is no "!" on the note window: a failed write is signalled only by the "!" in the home window's title bar (tap to retry) and the red dot on the list row.
- **Editing**: tap ✎, or tap the already-selected card again (the tap that hands focus to the window does not count; taps within 600 ms of gaining focus are ignored), and the card becomes a PICO `TextArea` in place (no auto-focus: you have to tap into the text to get a caret; Enter inserts a newline); a 200-code-point `CounterRing` appears at the bottom-right, and the strip below the card is reduced to a single ✓ (enabled while the text is not blank); the editor is at least 4 lines tall (164 dp) and grows with the text up to 254 dp, and the window grows with it; even if the note is stored folded, editing always shows the full editor. The round keyboard button that appears beside the card after tapping into the text is a system component of the PICO OS input method (`com.bytedance.pico.inputmethod`), not an app element: it appears only while some text field holds the caret and is how the system keyboard is summoned on the headset; the app cannot remove it, it just does not trigger it when ✎ is tapped. While editing, a 600 ms debounced autosave runs; ✓ or losing window focus ends editing (already autosaved); there is no cancel.
- **Creating**: the "+" in the home window's title bar opens a new note window straight into editing (a draft). `NoteSession` keeps only one draft at a time; tapping "+" again just brings the open draft window to the front; the draft counts toward the 30-note limit; only ✓ actually creates the note (its id is the window tag, so the window keeps its identity); a draft's strip has no ⤡ — it can be folded only once created; a blank draft is discarded and its window closed on ✓ / focus loss.
- **Deleting**: 🗑 in the strip or on a list row → PICO `AlertDialog` (`Orientation.Vertical`, 360 dp, fits inside the 400 dp note window): the title "Delete", a 300 dp yellow note preview (up to 3 lines), two icon-only buttons ✕ (cancel, secondary) / 🗑 (delete, danger), 120 × 52 dp with 28 dp icons; only the title "Delete" is text; while the dialog is open the note window temporarily grows to 400 dp tall, so even a folded or single-line window has room for it. On confirm, `NoteStore.delete` runs and the note window is closed, the same whether the deletion started from the list or from the note; the `deleted` flag guarantees nothing is written back afterwards.
- **Fold / unfold**: the ⤡ in the strip folds the note into the 96 dp folded marker `StickyMarker` (with an accent unfold badge), centred where the card was, and the window shrinks to the smallest height the system allows; a folded note has no strip (only the 2 dp outline when focused); a tap anywhere on the marker unfolds it back into the card. The folded state is saved with the note and it opens folded after a restart; the list order is unaffected.
- **Unfocused**: only the card (or the marker when folded), no strip; no save status is shown on the note (a failed write is signalled only in the home window).

## Technical notes

- **Containers**: two `Form.Planar` windows, Shared Space throughout — no Stage, no MR plane detection, no spatial anchors, and the Manifest requests no permissions. The home window `StickyNotesHome` is the `DefaultWindowContainer` (the Manifest declares 960 × 600 dp, `ContentSize`, `WorldScale.Dynamic`; content minimum 900 × 560 dp); the note window `StickyNoteWindow` is fixed at 400 dp wide with its **height pinned to the content height** (`ContainerResizeType.ContentSize`; `Main.kt` uses `windowConstraints(minWidth = maxWidth = 400.dp, minHeight = maxHeight = contentHeight)` to set min = max height to the content height, and the SDK resizes the container when the constraints change), `UniformResizable`, **no material background** (the yellow card sits directly in space), `CaptionBarType.Default`, `WorldScale.Dynamic` (still declared, but no code reads it any more), **one window per note**, tag = note id, bundle carrying `noteId` and a `draft` flag. The content height is measured by `NoteWindow`: the content column uses `Modifier.layout` to measure with an unbounded height (`maxHeight = Constraints.Infinity`) — a plain `wrapContent` would be clamped by the current window's maximum, and the window could then only shrink, never grow — adds the outer 12 dp top and bottom margins and reports it via `onContentHeight`; `Main.kt` clamps it to 120–400 dp. Inside the window the `StickyCard` (328 dp wide, 20 dp corner radius, height following the text) sits at the top (12 dp content margin + 24 dp card top padding, so the card's top edge is 36 dp from the window's top edge), with an always-reserved 60 dp strip slot 12 dp below it (the `ActionStrip` is centred in it; the reservation keeps the window from jumping on focus / unfocus); when folded the slot is no longer reserved. Window heights observed on the emulator: 1-line note 194 dp (24 + 74 + 12 + 60 + 24), 2 lines 220 dp, editing 284 dp; folded requests 144 dp, but PICO OS has a window minimum of about 180 dp, so the system caption bar ends up about 36 dp below the marker. While the delete dialog is open the window is temporarily opened to 400 dp so the dialog is not clipped; the system caption bar is outside the window; the home window's content is covered with a near-white scrim (`Tokens.Canvas` at 85% opacity) over the system material glass so a dark environment does not turn the panel grey.
- **Home window**: `PicoTheme` `TitleBar`, the app icon (`ic_note`) on the left, and on the right a danger "!" (shown only after a write failure / while `dirty`; tap → `NoteStore.retrySaveAsync`) and a round accent "+" wrapped in a capacity ring (n / 30, n = stored notes + drafts; at 30 the ring turns danger and the button is disabled and turns secondary). List rows: a 40 dp yellow mini-card (accent dot top-right = the note window is open, danger dot bottom-right = unsaved), a one-line summary (the first non-empty line, at most 60 code points), a 46 × 40 danger 🗑; tap a row to open / bring forward that note's window. Empty state: a note glyph + a large "+".
- **Per-window system title**: the first ≤ 12 code points of the note are written to `Activity.title` and the `TaskDescription`, so several note windows can be told apart in the system; a blank draft keeps the app name.
- **Fold / unfold (manual)**: v1.3 has no distance estimate at all and does not read the head pose. In `NoteWindow`, `collapsed = !editing && note.collapsed`: the strip's ⤡ (`ic_collapse`) calls `NoteStore.setCollapsed(id, true)`, the card's place is taken by the 96 dp `StickyMarker` (folded mini-note + 32 dp accent `ic_expand` badge, centred where the card was), and the marker's `onClick` writes `false` back. ⤡ is rendered only when `note != null` (a draft cannot be folded); editing takes precedence over the folded state (the full editor is always shown while editing); when folded the strip slot is not rendered and the window shrinks to the system minimum; `setCollapsed` commits under the lock but does not touch `updatedAt`, so the list order is unchanged.
- **UI**: PICO Spatial UI — `PicoTheme`, `TitleBar`, `TextArea`, `IconButton`, `AlertDialog` (delete confirmation; its buttons are `IconBtn` icons too); custom-drawn `IconBtn` (default 56 × 48 dp, 30 dp icon, three roles: Secondary / Danger / Accent), `ActionStrip` + `StripDivider`, `StickyCard` (328 dp wide, `heightIn(min = NoteCardMinHeight 74 dp, max = NoteCardMaxHeight 254 dp)`, padding 24 dp horizontal / 22 dp vertical, height = lines × 30 + 44, more than 7 lines `verticalScroll` inside the card), `StickyMarker` (96 dp), `CounterRing` (20 dp ring; turns accent at 80%, danger at the limit), `DeleteConfirmDialog`; the inline editor `EditingCard` uses `heightIn(min = NoteEditorMinHeight 164 dp, max = 254 dp)` + `minLines = 4`. Note body style `Tokens.noteTextStyle`: 20 sp on an exact 30 dp line pitch, with `LineHeightStyle(Trim.None)` — Compose (PICO fork) trims the first and last line's half-leading by default, so n lines would measure 30n − 6 dp; Trim.None makes the 1-line / 7-line cards exactly 74 / 254 dp. Icons are 24 dp stroked vectors `ic_{edit,delete,check,close,expand,collapse,plus,error,note}`; the card and the marker use a plain `clickable(interactionSource, indication = null)` without indication and no longer attach `spatialHoverEffect` or the default press feedback (on PICO OS 6.1 those two kept taps from reaching the card). Colour tokens are taken from the Figma page「02 本地组件」(02 Local Components) (`ui/Tokens.kt`: Canvas `#F4F5F1`, Ink `#1F2A25`, Muted `#6A756E`, Border `#CAD2C6`, Accent `#2E5F4B`, Secondary `#DCE4D9`, DangerBg `#F0D9D3`, DangerText `#8C3B2D`, NoteFill `#F5E9A9`, NoteInk `#2B2F27`, Pill `#F6F7F3`).
- **Data**: the `NoteStore` singleton; `files/notes.json` is a single JSON array (id / text / createdAt / updatedAt / collapsed; an old file without a `collapsed` key reads as false). Every mutation updates memory first inside a `Mutex`, then writes to disk on the IO thread: write `notes.json.tmp`, then `rename` (falls back to overwriting the file directly on failure); `create(id, text)` is idempotent (an existing id is treated as an update), and the existence and capacity checks are inside the lock; the commit section is `NonCancellable`, guaranteeing that `dirty` / `unsavedIds` always reflect the real outcome; a failed write → `dirty` + `unsavedIds` → the "!" appears in the home window's title bar (tap to retry) and a danger dot on the list row; the note window itself shows nothing. On startup notes are loaded sorted by `updatedAt` descending, and new notes go to the top (edits do not re-sort within the session, but do update `updatedAt`, so after a restart notes are re-sorted by `updatedAt`; `setCollapsed` changes only the folded state and does not touch `updatedAt`, so folding / unfolding never changes the order). `NoteStore.scope` (`SupervisorJob` + IO) carries writes that must complete after the window has closed (closing right after ✓, autosave on focus loss).
- **Limits**: **200 code points** per note (`codePointCount`; a CJK character or a single-code-point emoji counts as 1, combined emoji count by their code points; truncated automatically while typing); at most **30 notes** (enforced both by the home window's "+" and by `NoteStore.create`); a blank note cannot be confirmed with ✓.
- **Review fixes** (2026-09-14, three-perspective adversarial code review; all re-verified on the emulator): the draft window closed itself right after "+" (now only a real focus loss ends editing); a deleted note that was open got resurrected by the dispose write-back (`deleted` / `wasPersisted` flags); `NoteStore.create`'s check and write were not under the same lock (now idempotent inside the lock); a write cancelled mid-way lost the `dirty` flag (`NonCancellable` commit); the note-side "!" retry was first merged into the strip and then removed entirely at the user's request (retry lives only in the home window's title bar); the 480 dp delete dialog overflowed the 400 dp window (changed to `Orientation.Vertical`, 360 dp); `ImeAction.Done` swallowed newlines; the editor auto-focused (reverted at the user's request: no auto-focus, and tapping ✎ no longer pops up the system keyboard button); synthetic timestamp titles and dead-code cleanup.
- **Entry point**: `SpatialApplication.onCreate` → `NoteStore.init` → `launch(::mainApp)`; `LaunchActivity` extends `SpatialLaunchActivity`.

## Emulator testing (no debug broadcast channel)

This app has no separate debug broadcast channel; every action goes through the real UI (verification environment: PICO Emulator 6.1, AVD `Pico_Emulator_6_1`, PICO OS 6.1, 2160 × 2158, pico-cli 0.5.0). The emulator does not support scripted spatial-ray input, so tests use `--layerid` to project taps onto the surface of the currently focused window — the coordinates are within that window's own surface, not screen coordinates; the note window's surface is 800 × H px (400 dp wide, height varying with the content, origin unchanged, so for a given content height the coordinates are fixed), and the home window has its own surface:

```bash
adb shell input tap <x> <y> --layerid       # tap an icon (+ / ✎ / ✓ / 🗑 / ! …) or the card inside the focused window
adb shell input text "Hello"                # type (ASCII only); the editor does not auto-focus, so tap the TextArea first to give it the caret
adb logcat -s NoteStore                     # write-failure log
```

The write-failure scenario is triggered by making the `files/` directory read-only with `adb shell run-as com.example.spatialstickynotes chmod`; after restoring it, tap the "!" in the home window's title bar to retry. Tap the TextArea before typing to get the caret; the round keyboard button that appears beside the card at that point comes from the PICO OS input method (`com.bytedance.pico.inputmethod`) and is not part of the app. Dragging a note window still has to be done in the emulator by dragging the system caption bar with the mouse. v1.3 tap coordinates (px) on the note window's surface: the right half of the card (680, 180); ✓ while editing (400, 484); the strip on a 1-line note ✎ (254, 304) / 🗑 (400, 304) / ⤡ (546, 304), and on a 2-line note the strip is at y = 364; the folded marker (400, 240); delete dialog ✕ (277, 550) / 🗑 (565, 550). **Observed on the emulator only**: `--layerid` taps projected into the roughly 300 × 104 dp region at the note window's top-left are swallowed (presumably the system caption bar's input window), so the scripts always tap the right half of the card; not reproduced or verified on the headset.

The v1.3 build was verified on the emulator: open a note → adaptive 1-line card + ✎ / 🗑 / ⤡ below it, window shrinks to 194 dp; tap the card → editing, window grows to 284 dp, ✓ returns to the card; ⤡ → marker, window 180 dp, `collapsed: true` in `notes.json`; tap the marker → card, `collapsed: false`; restart → the folded note still opens folded; 2-line note → taller card (window 220 dp). Not verifiable on the emulator: overall behaviour on a real device (the headset was not connected on 2026-09-14) and the keyboard pop-up behaviour on a real device.

## Project layout

- `app/src/main/java/com/example/spatialstickynotes/`
  - `Main.kt` entry DSL (two WindowContainers; the note window's `windowConstraints` update with the content height) · `platform/` Application and LaunchActivity · `content/` `HomeWindow` home window / `NoteWindow` note window (including the content-height measurement and `EditingCard`) / `Windows` constants and bundle · `ui/` `Components` (IconBtn, ActionStrip, StripDivider, StickyCard, StickyMarker, CounterRing, DeleteConfirmDialog) and `Tokens` colour and size tokens (`NoteCardMinHeight / NoteCardMaxHeight / NoteEditorMinHeight`, `noteTextStyle`) · `data/` the `Note` model (with `collapsed`), `NoteStore` persistence, `NoteSession` runtime state (open / draft windows); the `lod/` package was deleted together with the distance LOD
- `app/src/main/res/drawable/ic_*.xml` 24 dp stroked icons
- `deliverables/` emulator screenshots and verification sheet (Excel), screenshots, and `archive-v1.1/` older material
